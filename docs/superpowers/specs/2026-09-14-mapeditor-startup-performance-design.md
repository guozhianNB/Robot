# 地图编辑器启动性能修复设计

## 目标

消除地图编辑器启动时的长时间不可用，并降低默认 SSH 地图存储模式下的首屏延迟。保持现有 HTTP API、响应结构、页面布局和地图文件真相模型不变。

## 已确认根因

1. FastAPI lifespan 同步等待所有 MCP 服务完成握手。单个失败服务可阻塞至 `MCP_CONNECT_TIMEOUT=60` 秒，期间整个后端尚未开始服务。
2. 地图 HTTP 路由声明为 `async`，内部却直接执行同步 SQLite、SSH/SFTP、PGM 解析和 PNG 编码，阻塞主事件循环。
3. `App.vue` 与常驻的 `PlacePanel`、`ZonePanel` 同时读取地点和区域，首屏各产生两次相同请求。
4. `/api/map/current` 每 2.5 秒轮询；收到 ROS `/map` 后，每次都会重新列举并读取所有地图计算指纹。

## 设计

### MCP 启动

`mcp_client.start()` 只负责创建专属线程和调度连接任务，立即返回，不再调用 `Future.result()` 等待连接完成。连接状态继续通过现有模块状态接口逐步呈现。连接失败仍按既有降级约定记录审计和警告，不影响后端启动。

增加启动代次标识，避免停止后仍在运行的连接任务回写已清理状态。`stop()` 取消尚未完成的连接 Future，再关闭已建立的会话和事件循环。重复调用 `start()` 保持幂等。

### 地图路由

保留现有同步领域函数。所有可能访问地图存储、解析整图或同步标签缓存的异步路由，通过 `asyncio.to_thread()` 调用同步函数。轻量纯内存响应可留在事件循环中。

本次优先覆盖首屏路径：地图列表、当前地图、地图元数据、PNG、地点、区域和地图编辑器状态。写接口不改变事务顺序；若纳入线程执行，仍以一次完整同步函数作为工作单元，避免拆开原子操作。

### 前端数据所有权

`App.vue` 继续作为画布所需地点和区域数据的唯一请求方，并把结果作为 props 传给两个面板。面板删除自己的列表请求和 `mapName` 监听加载逻辑，编辑完成后只发出 `changed`，由父组件刷新一次并把新列表传回。

初始化改为：先并行读取地图列表和轻量状态；确定地图后，再并行读取该地图的元数据、地点和区域。画布仍由 `mapName` 驱动独立加载 PNG。

### 当前地图轮询

为 `locator.current_map()` 的指纹匹配结果增加短时缓存。缓存键至少包含 ROS `/map` 四项指纹以及地图列表可观察版本；短时间内相同输入直接复用结果。地图写入、重命名、复制、删除或元数据修改后清除缓存。

前端状态轮询保持现有展示语义，但禁止重叠执行：上一次 `statusTick()` 未结束时跳过下一次 tick，避免网络慢时请求堆积。

## 错误与降级

- MCP 后台连接异常只更新状态并审计，不抛到 lifespan。
- `asyncio.to_thread()` 中的 `MapStoreError` 继续由现有路由转换为原响应，不改变状态码和字段。
- SSH 不可达时继续使用既有离线缓存；性能改动不放宽写操作失败规则。
- 页面任一数据请求失败时，其余请求仍可完成并显示已有降级提示。

## 测试与验收

1. 单元测试证明 `mcp_client.start()` 在连接协程被阻塞时仍快速返回，并验证停止期间的清理行为。
2. 路由并发测试用阻塞的假 MapStore 证明一个慢地图请求不会阻塞轻量健康请求。
3. 前端静态/组件测试证明初次选图只请求一次地点和一次区域，状态轮询不会重叠。
4. 当前地图缓存测试证明相同指纹在 TTL 内只扫描一次，地图变更后会重新扫描。
5. 运行 `tests/test_mapeditor.py`、相关 MCP 测试、前端类型检查和 mapeditor 构建。
6. 浏览器复验首屏内容与 Canvas 正常，后端启动不再等待 MCP 的 60 秒连接超时。

## 非目标

- 不合并或重命名现有地图 API。
- 不修改地图编辑器视觉设计。
- 不改变 `.tags.json` 唯一真相、SSH/local 双模式、备份或审计协议。
- 不重写 PGM 编解码与 Canvas 渲染。
