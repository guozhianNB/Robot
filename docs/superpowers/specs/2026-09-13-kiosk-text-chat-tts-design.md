# Kiosk 输入框回复逐句自动播报设计

日期：2026-09-13  
状态：设计已确认，待书面规格审查

## 一、目标与范围

车载端 kiosk 通过输入框发送消息后，大模型回复仍以 SSE 增量文字实时显示，同时由后端按完整句依次调用当前 TTS 引擎并通过机器人扬声器播报。

本功能只由 kiosk 启用。admin 管理端以及未升级的 API 调用方保持静音。语音麦克风问答链路的现有行为不变。

## 二、接口契约

`POST /api/chat` 请求体增加可选字段：

```json
{
  "uid": "elder_001",
  "message": "你好",
  "thinking": "auto",
  "speak": true
}
```

- `speak` 默认为 `false`，确保 admin 和现有调用方兼容。
- kiosk 明确发送 `speak: true`。
- SSE 响应协议不变，继续输出 `meta`、`reasoning`、`content`、`tool_start`、`tool_result`、`done`、`error`。
- 播报是附加能力，不改变 `/api/chat` 的 HTTP 状态和 SSE 内容。

## 三、后端数据流

`chat_route` 在 `speak=true` 时创建一次“文本回复播报会话”。每收到一个 `content` 事件，先照常向前端发送，再把同一段文字非阻塞地投递给播报会话。收到 `done`、`error`、生成器异常或客户端结束时关闭播报会话。

播报会话在后台线程中顺序消费文字增量：

1. 使用现有 `SentenceBuffer` 按 `。！？`、换行和长度上限切句。
2. 使用现有 `sanitize_tts_text` 清理句子。
3. 使用 `VoiceWorker` 已选中的实际 TTS 引擎逐句合成；云端单句失败时沿用本地 TTS 兜底。
4. 将音频依次送入现有 `AudioSink`，保持句间顺序且不重叠。
5. 流结束时 flush 未带终止标点的尾句，并调用 `end_of_stream()` 自然收流。

HTTP/SSE 生成线程只负责投递文字，不等待云端合成和播放，避免 TTS 网络延迟拖慢前端逐字显示。

## 四、并发与状态

文本回复播报复用 `VoiceWorker` 的轮次代数、打断标志、TTS 引擎和声卡输出，不创建第二套声卡对象。

- 新的 kiosk 输入框播报会取代尚未完成的上一轮回复，并清掉其待播音频。
- 麦克风产生的新语音问答也可取代输入框播报；两条链路共享“最新轮拥有播报权”的约束。
- 输入框可以在会话状态为 `IDLE` 时发起播报。首句音频准备完成后，状态机先进入 `LISTENING`，再进入 `SPEAKING`，从而继续复用现有播放完成与插话打断逻辑。
- 文本播报不发布 `chat_new`，也不调用 `post_turn_fn`；历史入库和记忆整理仍只由 `/api/chat` 原有收尾逻辑执行一次。

## 五、降级与错误处理

- `speak=false`：完全不创建播报会话。
- `tts_enabled=false`：接受请求但不合成，文字 SSE 正常。
- 语音模块不可用、worker 未启动或声卡不可用：播报入口返回不可用状态，`/api/chat` 继续返回文字。
- 单句云端 TTS 失败：写入 `voice_error` 审计并尝试本地 TTS；本地也失败则跳过该句。
- 播报后台异常：写入审计并安全结束该轮，不得中断 SSE 或后端主进程。
- 客户端断开或聊天流异常：关闭文字投递，后台只处理已经接收的完整句；未完成尾句不继续播报。

## 六、代码边界

- `LLM/server.py`：扩展 `ChatRequest`，在 `/api/chat` 中桥接 SSE 增量和播报会话。
- `LLM/voice_api.py`：提供启动、投递和结束文本回复播报的降级安全门面。
- `LLM/voice/worker.py`：实现与现有语音问答共享引擎、播放队列和轮次控制的文本播报会话。
- `frontend/packages/kiosk/src/App.vue`：输入框请求增加 `speak: true`。
- admin 不改动；共享 SSE 事件定义不改动，因为没有新增总线事件。

## 七、测试与验收

后端单元测试覆盖：

- `ChatRequest.speak` 默认值为 `false`。
- `speak=false` 不触发播报门面，SSE 内容保持原样。
- `speak=true` 按顺序投递全部 `content` 增量并正常结束。
- 聊天流异常时关闭播报会话，异常不改变既有错误处理。
- worker 按完整句顺序合成并播放，结束时 flush 尾句。
- 新轮取代旧轮，旧轮不再合成或入队。
- TTS 关闭、worker 停止和合成失败均不影响文字回复。

前端构建验证 kiosk 请求包含 `speak: true`，admin 请求不包含该字段。

人工验收：启动本地后端与 kiosk，输入包含至少两句的消息；应看到回复文字持续增长，并在每个完整句生成后依次听到云端音色播报。随后从 admin 发送消息，机器人不得播报。

## 八、非目标

- 不增加浏览器 Web Speech API。
- 不让 admin 自动播报。
- 不新增独立聊天接口或修改 SSE 事件协议。
- 不改变麦克风语音问答的历史、声纹或打断规则。
- 不提供“重播”“暂停”“音量调节”等额外控制。
