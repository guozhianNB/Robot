## 1. 系统全貌与运行分工

```
┌─────────────────── PC（开发/演示主机，后端默认跑这里）───────────────────┐
│  LLM.server            :8000   大模型端主后端（对话/语音/记忆/Plan/通知/车控）│
│  LLM.mapeditor_server  :8010   地图编辑器独立进程（34 条 /api/map* 路由）    │
│  vision.camera_server  :9540   摄像头共享服务（裸 TCP，NV12 分发）           │
│  /admin /kiosk /nurse  静态托管（由主后端挂载 dist）                        │
└───────────────┬───────────────────────────────┬─────────────────────────┘
                │ rosbridge ws :9091            │ SSH（MAPS_IO=ssh）
┌───────────────▼───────────────┐   ┌───────────▼──────────────────────────┐
│ 板卡 RDK X5（Ubuntu22.04/Humble）│   │ 板卡 ros2_car/maps/ ← 地图"唯一真相"   │
│  ROS2：slam_toolbox / Nav2       │   │  <图名>.yaml / .pgm / .tags.json     │
│  robot_chassis → USB CDC         │   └──────────────────────────────────────┘
│  robot_actions（move/turn/nav）  │
│  rosbridge :9090(Foxglove)/:9091 │
└───────────────┬──────────────────┘
                │ USB CDC 帧 [AA][55][len][cmd][payload][xor]
┌───────────────▼──────────────────┐
│ STM32F103ZETX 固件：麦轮逆解/PID  │
│ 编码器 odom/IMU(USART3)/OLED     │
└──────────────────────────────────┘
```

**一句话分工：** PC 出"大脑"（模型、记忆、计划、UI），板卡出"腿和眼睛"（ROS2 导航、底盘、传感器、地图真相），STM32 出"肌肉"（实时电机控制）。

**分层铁律（改代码前必看）：** LLM 包内依赖单向 `core → store → agent → server`，下层绝不 import 上层；`conf.py` 位置不可动（`BASE_DIR` 靠它定位 `.env`）。

## 2. 各链路现状

> 状态图例：✅ 已验证（有实测/验收记录）｜🟡 代码就绪但未做真机验收｜🟠 部分占位或空转

### L1 对话链路（大模型端主体）

- **做什么：** 老人说一句话 → 检索记忆 + 注入角色提示词 → DeepSeek 流式生成 → 边说边调工具 → 播报并落库审计。
- **闭环在哪：** `LLM/server.py::chat_route` → `LLM/agent/chat.py::chat_stream`（SSE 事件 `meta/reasoning/content/tool_start/tool_result/done/error`）→ `agent/tools.py::run_tool`（本地工具 + MCP 工具统一分发）→ `store/db.py::append_history` + `core/log.py`。
- **上下文组成：** `base.md`（共用人设 + 红线）+ 角色片段（`ward/elder/admin.md`）+ `react.md` + 记忆召回 + 病房集体层上下文 + 时间。
- **思考档位：** 五档 `auto / none / low / high / max`（`server.py` 解析，`conf.DEFAULT_SETTINGS.thinking_mode` 持久化）。**踩过的坑写进规格了：** `reasoning_effort` 必须是顶层参数，塞进 `extra_body` 会被 DeepSeek 静默忽略（`2026-09-17-thinking-mode-switch-design.md` D5）。思维链只上屏、**绝不进 TTS、不落库**，由测试锁死。
- **工具循环：** `conf.REACT_MAX_TOOL_ROUNDS = 4`（注意：`AGENTS.md` 里仍写"最多 2 轮"，已过期）。
- **状态：** ✅ 有界 ReAct 2026-09-18 落地（80 passed）。

### L2 语音链路（唤醒 → 播报 → 打断）

- **闭环在哪：** `LLM/voice/voice_api.py::start_voice`（lifespan 内 `bus.start_drain` 之后、`mcp_client.start` 之前拉起）→ `voice/worker.py`（状态机 IDLE→LISTENING→SPEAKING）→ `kws.py` 唤醒 → `asr.py`/`asr_cloud.py` 流式识别（开口回补 0.5s、`asr_partial` 实时字幕）→ `speaker.py`（ERes2NetV2 声纹，阈值 0.40 为实测标定）→ `agent/session.py` 定会话主体 → `chat_stream` → `tts_buffer.py` 句级合成 → barge-in 打断。
- **两处刻意设计：** ① 云端 ASR/TTS 构造失败自动回退本地；② 思维链不合成语音（`worker._consume_events` 只对 `content` 分句）。
- **状态：** ✅ 功能闭环；🟡 "声纹→角色→分层提示词"这条链**在本机只有单测覆盖，未接麦克风整链实测**（`docs/log.md` 2026-09-14 续三）；🟠 方言识别按决策整体后置。

### L3 记忆链路（RAG + 核心记忆 + 图谱）

- **闭环在哪：** `LLM/agent/memory.py::recall_v3`（四层：档案查表 + core 记忆 + RAG top3 + 图谱一跳）、`note_turn` / `consolidate`（空闲 30s 触发、租约、`external_id` 幂等、向量去重、医疗红线拒绝写入）、`correct_instant` / `correct_from_feedback`（软删→回收站→Chroma 失效）、`store/ragstore.py`、`store/graph.py`（Kuzu）。
- **红线：** `MEDICAL_KEYWORDS` 命中一律拒写；画像 pinned + 防退化；`expressions` 语录需人工审核。写入走"半自动确认"（自动沉淀 + 人工可改 + 拿不准进待处理）。
- **状态：** ✅ 主链闭环；🟠 **图谱写入没有生产者**——`CONSOLIDATE_PROMPT` 只要 `entries/digest/portrait/expressions`，而 `memory.py` 读取 `data.get("relations")` 才写 Kuzu，导致图谱读侧实现了、写侧几乎不触发（"图谱腿空转"）；🟠 `ragstore.query()` 在 chromadb 不可用时直接 `return []`，未实现 v3 规格 §8 的 SQLite 镜像兜底。

### L4 角色与权限链路（三层用户体系）

- **闭环在哪：** `agent/session.py::derive_role`（**uid→role 的唯一权威，按 `profiles.kind`，不靠 uid 前缀**）、双槽会话 `kiosk|admin`、`get_principal(X-Surface)`、`tick()` 每秒（admin TTL 到期降权 + 病房位置自动切换，debounce=3）→ `agent/policy.py::role_policy`（未知角色 fail-closed 落集体层）→ `tools.effective_tools`（per-tool 开关 ∩ 角色白名单 ∩ MCP `roles`）→ 接口闸门。
- **五条红线：** R1 前端 role 不可信；R2 fail-closed；R3 急停/呼救永远放行；R4 医疗写入红线与角色无关；R5 层级上下文单向（老人私聊绝不回灌集体层）。
- **状态：** ✅ P0 已收口；🟠 **`/api/memories/*`、`/api/reminders/*`、`/api/tools*`、`/api/voice/*`、`/api/vision/*`、`/api/context`、`/api/system/shutdown` 这些族目前不校验角色**（`limit.md` §3 自己列着，只有管理端 UI 与 `X-Surface` 语义区分）。

### L5 提醒 → 通知链路（护士台数据面）

- **闭环在哪：** `agent/reminder.py` 独立调度线程（15s tick，状态机 `pending→triggered→confirmed/unconfirmed/missed`）→ 首次 `triggered/missed` 时按 `(source_kind, source_id)` **幂等建一个 manual Plan** → `agent/notify.py::ingest()`（**通知中心的唯一写入口**：归一化→去重合并→落库→审计→广播）→ 前端护士台。
- **关键口径：** 合并键 = `(source, type, uid, 正文)`，**合并时级别只升不降**（少了正文会把同分钟内的不同事互相吞掉、critical 被静默降级——这是 2026-09-18 修订的原因）。
- **上报出口：** MCP 子进程 `LLM/notice_mcp/`（工具 `notify_nurse`），三层角色都给（声纹识别失败会 fail-closed 落到集体层，那里堵死等于"老人求助喊不出来"）。
- **状态：** ✅ 端到端实测通过（`docs/log.md` 2026-09-18）；🟠 报警的**微信/企业微信/短信推送仍未做**，只有库 + SSE + 护士台页面。

### L6 Plan 计划 + 车控链路（本项目最有分量的工程）

- **闭环在哪（从指令到轮子）：**
  `LLM/tool/plan_tool.py::create_plan`（LLM 只能提交候选，P1–P3）→ `agent/plan.py`（编译步骤、地点/区域固化成坐标 + 地图名 + tags 指纹）→ `store/db.py`（plans / plan_steps / plan_step_attempts，版本乐观锁，来源幂等索引）→ `agent/plan_scheduler.py`（独立 daemon 线程，1s tick；三层解析 MCP 返回；按 `car_task_id` 对账，**只有明确终态才推进**；重启遗留移动步骤进 `needs_review`，绝不自动重发车）→ `agent/action_gate.py`（对话与 Plan 共用的**单车动作槽**，Plan 占用时普通车控返回 busy，`robot_status`/`robot_stop` 始终放行）→ `tools.run_plan_tool()`（只放行车 MCP 白名单，不继承创建者角色）→ `LLM/car_mcp/car_server.py`（七工具 stdio MCP）→ `car_link.py`（四条连接：Ctrl/Stop/State/Probe）→ rosbridge :9091 → `ros2_car` 的 `robot_actions`（`/robot/move|turn|navigate_to|readiness`）→ Nav2 → `robot_chassis` → USB CDC → STM32。
- **API / 事件：** 七组免鉴权 Plan API + `POST /api/nurse/page-unlock`；事件 `plan_created/plan_updated/plan_step_changed/plan_needs_review`；回报走 `notify.ingest(source="plan", ...)`。
- **安全设计：** 执行白名单、不继承权限、结果不确定不重试、地图名/tags 指纹变化拒绝执行、急停永远放行。**所有自动化测试用 fake MCP，禁止借验收真发车。**
- **状态：** ✅ 第一期落地并验收（2026-09-21：后端聚焦 241 passed、`LLM/tests` 656 passed/1 既有失败、四端构建通过、Edge 浏览器验收）；🟡 **真实底盘串行执行、途中急停、AMCL 定位精度、现场网络访问仍属未验项**；🟠 第二期"完整抢占"、第三期"受限动态重规划"未做。

### L7 地图与定位链路

- **唯一真相：** `<地图名>.tags.json`（与 `.yaml/.pgm` 同级），读写入口 `LLM/maps/maptags.py`；`brain.db` 的 `map_tags_manifest/destinations/zones` **只是单向索引缓存**（文件→库，可丢弃重建）。**违反就会重演"两套真相"事故。**
- **文件 IO：** `maps/mapstore.py`（`LocalMapStore` / `SshMapStore`，paramiko 优先、退回 ssh.exe 子进程；`MapCache` 断连回退 stale；名字白名单；保存前自动备份到 `.backup/`）。
- **渲染与几何：** `maps/mapserver.py`（纯 stdlib PGM/灰度 PNG）、`core/zonegeo.py`（射线法点入区）。
- **定位：** `maps/roslink.py`（rosbridge websocket）→ `maps/locator.py::current_map()`，**第一权威 = `map_server` 的 `yaml_filename`**，读不到才退回 `/map` 元数据指纹（像素编辑器"另存"出的副本与原图元数据天然一致，指纹反查必然多命中——这是必须改第一权威的原因）。
- **病房自动切换：** `session.tick()` + 位置判定 + debounce + 手动覆盖窗口。
- **编辑器：** A 篇 `frontend/packages/mapeditor/`（看图/标点/划区/管文件）；B 篇 `public/pixel-editor.html`（上游 MIT 工程只改 6 处）+ `maps/mapapi.py::map_save`（备份→原子写→审计→返回 `restart_hint`）。**改完地图必须重启导航才生效。**
- **状态：** ✅ A/B 篇 + 独立进程按需启动（主后端 8000 已 404，测试 `test_map_service_split.py` 锁死）；🟡 `MAPS_IO=ssh` 真机读写未验、编辑器真实 `vite build` + 浏览器联调未做、板卡真机验收未跑；🟠 已知前置问题：地图未知率高（60.7%~85.1%）、AMCL 位姿不稳。

### L8 视觉与人脸链路

- **闭环在哪：**

## 5. 汇报时可主动说的风险点

1. **单点依赖 rosbridge :9091**：`nav_screen.sh kill all` 会连它一起停且不自动恢复，症状表现为"车体未就绪 Connection refused"——**长得像车坏了，其实是桥没起**。排查先 `ss -lnt | grep 9091`。
2. **AMCL 静止时不发 `/amcl_pose`**（`update_min_d/a` 使然），所以"位姿不可用"是配置现象；发车前必须确认已定位，否则是在错先验上导航（实测发车那刻 AMCL 报 (0,0,0)、真值 (0.48,−0.21)）。
3. **rosbridge 订阅按 topic 共享**，Foxglove 的 `cbor-raw` 会污染同 topic 的普通 JSON 客户端 → 后端必须走专属 9091，Foxglove 用 9090。
4. **Plan API 全部免鉴权**：知道接口的人可绕过护士台 PIN 直接调级/取消。这是**用户明确接受的产品边界**（`plan表设计-初版.md`:335），汇报时别被当成漏洞。
5. **隐私红线**：人脸/指纹/声纹绝不许进 GitHub；提交前跑 `python scripts/check_privacy.py`，`.gitignore` 不构成保证（声纹样本曾真的进过 `origin/main`）。
6. **红线靠关键词匹配**，语义改写可绕过；`_pending_turns` 是内存态，重启丢沉淀缓冲。
7. **`admin_auth_required` 可被关闭**，关掉后 `login_admin` 免口令即得 admin（UI 有警示，但这是真实可被绕过的路径）。
