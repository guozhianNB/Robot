# 记忆系统差距分析：MaiBot (A_Memorix) vs 本陪护机器人

> 对照材料：`docs/maibot/memory-system.md`、`docs/maibot/learning.md`
> 本实现：`LLM/memory.py`、`LLM/db.py`、`LLM/chat.py`、`LLM/vectors.py`、`LLM/server.py`、`UI/index.html`
> 整理日期：2026-08-19

## 一、一句话结论

**本项目的记忆"存储、沉淀、审核"骨架已搭好且比 MaiBot 更严格（医疗只读、半自动确认、TTL），
但"检索使用"这一环是断的——对话时向量记忆从未被真正检索注入，摘要不进检索、无纠错闭环、
无图谱/导入/回收站/维护机制。要达到 MaiBot"越聊越懂你"的效果，优先补检索链路与纠错闭环。**

---

## 二、能力对照表

| 能力（MaiBot） | MaiBot 做法 | 本项目现状 | 差距 |
|---|---|---|---|
| 长期记忆检索 | 按话题/人物/时间/经历多维检索 | 结构化查表 + 字符 n-gram 向量 Top-K | ⚠️ 检索链路断（见差距 1） |
| 人物画像 | 多条目结构化画像（基本信息/性格/偏好/重要记忆），WebUI 可修正 | 单段 ≤150 字文本，LLM 整体覆盖，WebUI 只读 | ⚠️ 差距 4 |

| 知识图谱 | 实体-关系图，WebUI 可编辑 | 无 | ❌ 差距 5 |
| 来源管理 | 记录来源（聊天流/导入/资料），可筛选批量处理 | 只有 `source="llm"/"manual"` 粗字段 | ⚠️ 差距 9 |
| 自动写回 | 人物事实写回 + 聊天摘要写回，频率/范围配置化 | 话题结束批量 consolidate（空闲 30s / 上下文满） | ✅ 基本对齐 |
| 导入中心 | 粘贴文本/上传文件/迁移历史批量导入 | 仅逐条人工录入 | ❌ 差距 6 |
| 反馈纠错 | 查询后结合后续反馈标记/修正旧内容 | 仅整理时 conflict 检测 | ❌ 差距 3 |
| 记忆维护 | 强化/削弱/长期保留/遗忘 | TTL 到期删除 + 手动删除 | ⚠️ 差距 8 |
| 删除恢复 | 删除前预览、回收站/操作记录恢复 | 物理 DELETE，无回收站 | ❌ 差距 7 |

| 说话风格学习 | 学口头禅/语气/黑话 → 笔记增量更新 + Few-shot 使用 | `style` 静态文本 + 画像里带风格描述，无语录库 | ❌ 差距 11 |

## 三、关键差距详析（按影响排序）

### 差距 1【最致命】对话时向量记忆根本没被检索——检索链路是断的

**证据链：**
- `chat.py:94` → `build_system(uid, settings)` 调 `rag.recall(uid, "")`（空 query）
- `memory.py:_vector_memory()` 用空 query 做向量检索
- `vectors.py:_embed("")` → 空向量 → `recall()` 里 `if s > 0` 全部过滤 → 返回 `[]`

**后果：** 每轮对话注入 System Prompt 的"记忆"实际只有：
1. 结构化档案（姓名/床号/病史/用药/称呼/话题）——查表，一直有效 ✅
2. `portrait` 画像整体文本
3. `summary` 摘要整体文本

而 `preference / event / fact` 类**向量记忆从未在对话中被使用过**。MaiBot 的核心价值"根据当前话题找回相关记忆作为回复参考"，本项目这一步等于没做——"上次聊过的话题""他喜欢的京剧"这类记忆只有恰好出现在整体注入文本里才会生效。

**修法：** `build_messages()` 里把「当前用户消息 + 最近 2 轮对话」作为 query 传入 `recall()`；`build_system` 增加 query 参数。

### 差距 2 摘要 / Episode 不进检索

- `consolidate()` 的 `digest` 只追加进 `summaries` 表（整体截断 900 字，每次全部塞进 System Prompt）；
- 老人问"上次我们聊了什么 / 那天你提醒我什么" → **无法命中检索**，只能靠整体注入碰运气；
- MaiBot 把聊天整理成可检索的 Episode 记忆。

**修法：** consolidate 的 digest 额外作为一条 `type=episode` 记忆入库（长 TTL 或无 TTL），可被向量检索命中。

### 差距 3 无"反馈纠错"闭环

场景：老人说"我不是姓张，我姓王""这药我不吃了""以后别叫我闺女了"——**明确的纠正信号**，目前没有任何机制写回档案/记忆。MaiBot 明确有"查询后结合用户反馈修正旧内容"。

**修法（陪护场景优先级高）：** 对话轮次后（复用 consolidate 或单独轻量分析）检测"纠正/否定/更新"语句 → 更新 profile 字段或对应记忆条目，并记审计。

### 差距 4 画像太粗、不可编辑、会退化

- 单段 ≤150 字文本，每次 consolidate 由 LLM 整体重写覆盖（`set_portrait` 直接 UPDATE），一次输出差就退化，无版本；
- 前端 `portrait-box` 只读展示（`index.html:593`），护工无法手动修正；
- MaiBot 画像分条目（基本信息/性格/偏好/重要记忆）且 WebUI 可改。

**修法（低成本）：** 前端画像区改为可编辑输入框 + 保存接口；或画像改结构化 JSON 字段。

### 差距 5 无知识图谱

MaiBot 用节点+关系表达"谁和什么有关"（人物关系、话题关联、事件关联）。陪护场景价值明确：老人的人际关系（"我女儿叫小红"）、兴趣关联（喜欢京剧 ↔ 孙子）、事件关联。本项目所有关系只能写进 content 文本，无法结构化查询。

**修法（低成本版）：** `memories` 加 `relations` JSON 字段，consolidate 时让 LLM 顺带提取实体关系；前端记忆条目展示"关系"标签。完整可视化图谱后置。

### 差距 6 无导入中心

MaiBot 可粘贴文本/上传文件批量导入背景知识（家属整理的喜好清单、健康资料）。本项目只能逐条 `POST /api/memories`。

**修法：** 新增批量导入接口（文本按行/段落切分入库，默认 pending）+ 前端粘贴框。

### 差距 7 无回收站 / 删除保护

`db.delete_memory()` 物理 DELETE。护工误删过敏史等关键记忆不可恢复 = 安全事故。MaiBot 删除前可预览影响、删除后可恢复。

**修法：** 软删除（`status=deleted` + `deleted_at`），新增回收站视图与恢复接口，定期物理清理。

### 差距 8 无记忆维护（重要性/强化/遗忘）

只有 TTL 过期 + 手动删除，没有 MaiBot 的"强化/削弱/长期保留/冻结/保护"。

**修法（低成本）：** `memories` 加 `importance`（0-5），检索排序按 `相似度 × (1 + importance·w)` 加权；前端"重要/普通"按钮。

### 差距 9 来源管理过粗

`source` 只有 `"llm"/"manual"`，无法定位"哪段对话/哪次导入"，无法按来源筛选/批量处理。

**修法（低成本）：** source 存 `"llm:consolidate" / "manual:nurse" / "import:xxx"`，`list_memories` 支持按 source 过滤。

### 差距 10 无检索调优与运行时自检

- `top_k=3` 硬编码在 `memory.py:76`，`DEDUP_SIM_THRESHOLD=0.55` 为常量，无设置入口；
- 无记忆系统健康检查端点（MaiBot 有 embedding/向量库/自动保存自检）。

**修法（低成本）：** `conf.py` 加 `MEMORY_TOP_K` 进 settings；新增 `/api/memories/health`（表完整性 + 向量索引可构建 + 统计）。

### 差距 11 无说话风格学习（对应 learning.md）

需求文档模块 3 定了"风格画像 + Few-shot 语录检索"双通道，但实现只有 `style` 静态文本 + 画像里带一句风格描述。MaiBot 学口头禅/语气/黑话并整理成笔记增量更新。**目前机器人说话风格是写死的，不会越聊越像老人。**

**修法（中等）：** consolidate 顺带提取"老人常用表达"（口头禅/称呼习惯）入库 `quotes` 表；`build_system` 注入 2-3 条高频语录作 Few-shot 风格示例（注意保持陪护机器人身份，不镜像复刻——这是本项目已定的红线，比 MaiBot 的"学群体风格"更克制）。

## 四、本项目已做对的部分（保持，别改坏）

- ✅ **医疗只读红线**（`MEDICAL_KEYWORDS` 拒绝模型写入）+ 写入分级（medical 人工 / preference pending / event TTL）——比 MaiBot 更严格，符合陪护安全
- ✅ **半自动确认**（pending + 前端审核 confirm/reject）——与 MaiBot"待处理"思路一致
- ✅ **话题结束批量整理**（空闲 30s / 上下文满触发，`consolidate()`）——与 MaiBot"按消息窗口整理"一致
- ✅ **去重 / 合并 / 冲突检测**（LLM 判断 + 服务端向量兜底）
- ✅ **混合检索路由**（事实查表 / 事件偏好向量）——设计正确，只是向量腿没接上
- ✅ **审计日志**（`audit.jsonl`，memory_change 全记录）——比 MaiBot 强
- ✅ **TTL 时效**（事件过期自动清除）——比 MaiBot 的"遗忘"更自动化
