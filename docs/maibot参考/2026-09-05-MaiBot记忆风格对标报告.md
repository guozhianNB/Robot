## 一、MaiBot 记忆子系统（A_memorix v2.0）关键机制

### 1. 写入链路
- **两条写入路径**：(a) 导入管线 = 策略感知切分（`core/strategies/`）；(b) **运行时对话写入 = `ingest_text`/`ingest_summary` 一条文本=一个 paragraph 直写，不走策略分块**（`ingest_service.py::ingest_text` L310）。
- **四策略分工**（只用于批量导入）：`narrative`=按 markdown 标题分场景+场景内滑窗（1600/400），LLM 抽 `{events, relations}`；`chat_log`=按 `[时间戳][发送者]` 头聚合；`factual`=结构感知按行切，LLM 抽 `{triples, entities}`；`quote`=按空行分 stanza，**零改写零 LLM 整段原文透传**。类型自动推断在 `type_detection.py`（quote>factual>narrative 词典打分）。
- **external_id 三层幂等**：① `external_memory_refs` 表 `external_id PRIMARY KEY→paragraph_hash FK`；② 写前查重命中即返回 `skipped exists`；③ `ON CONFLICT DO UPDATE` + 内存 in-flight 去重（`request_dedup_service`）。宿主摘要 external_id = `chat_auto_summary:{session}:{count}`（消息数单调递增保证不重不漏）。**约 20 行可复刻**。
- **段落+图谱同写**：非跨库事务，顺序=段落元数据（IMMEDIATE 事务内 add_paragraph，主键=内容 sha256，同事务 enqueue Episode 脏标记）→ 段落向量 → 实体+向量 → 关系 `upsert_relation_with_vector` + 桥表 `paragraph_relations` → external_ref。失败策略：向量失败入 `paragraph_vector_backfill` 队列带 warning 继续；关系向量行内状态机（none/pending/ready/failed）内部消化。原则：**事实先行落库、索引尽力而为、行内状态机+独立回填队列兜底**。
- **pending 队列是系统级模式**：DB outbox 表族（episode_rebuild_sources / paragraph_vector_backfill / person_profile_refresh_queue / storage_cleanup_jobs / memory_feedback_tasks…），行内 `status+due/next_attempt_at+lease_token`。写入侧只在写事务内 enqueue（revision++、5s debounce）；消费侧 `background_task_service` 注册 12+ asyncio loop（episode 1s 轮询 batch20 lease1800s、vector_backfill 60s…），租约心跳→revision CAS publish→失败指数退避 max3。**Episode 从不实时生成，永远后台沉淀**。

### 2. 检索链路
- **dual_path.py**：按 query_type 走段落/关系/双路/时间模式；双向量池 dual（段落池 top20 + 图谱池 graph_top40 映射回支撑段落做 evidence）；证据级加权（relation 1.0 / entity 0.55 / 语义 0.65 / 稀疏 0.20 / 图 0.15）+ 图可信度按支撑段落数校准。
- **sparse_bm25.py**：SQLite FTS5（tokenized shadow + char-2gram fallback），candidate_k=80，embedding 降级仍可读——不依赖外部服务的兜底腿。
- **graph_relation_recall.py**：query 种子实体受控图召回（direct pair → 两跳 → incident，跳过 inactive 关系）。
- **pagerank.py**：PersonalizedPageRank（alpha 0.85、timeout 1.5s、并发 4）把图重要性反馈到段落排序。
- **posterior_graph.py**：后验图补位 gate（默认关）——核心结果不足才从图补 relation 进尾部竞争，保 recall 不激进改排序。
- **score_calibration.py**（核心）：解决语义/稀疏/图谱分数不可比——每通道先校准（minmax/rank_percentile/sigmoid/softmax），再 `weighted_rrf` = 每通道转 RRF 排名分 `(k+1)/(k+rank)`（k=60）后加权求和（vector 0.7/bm25 0.3）。**180 行纯函数近乎可平移**。
- **threshold.py**：动态阈值 `adaptive=percentile(75)/mean−1.5σ/最大断层 取中位数`，clip [0.29,0.95]，`min_results=4` 兜底；**只按当次请求候选分数分布现算**，不跨请求反馈。
- 执行链：`memory_search_service`（mode=search/time/hybrid/episode/aggregate）→ 组装候选 → fusion → 动态阈值 → 后置过滤（人物/删除/stale/聊天 scope）→ 只对**最终返回且实际采用**的 relation 命中提交一次 ACCESS 强化。

### 3. 人物画像
- 证据 4 来源：memory_traits、relation_edges（图谱命中别名者）、vector_evidence（每别名双路召回 top12）、fact_claims（账本）。
- **画像证据必须显式绑定 person_id**（否则丢弃，防别名串人）；被反馈打过的段落硬过滤。
- **灵魂机制（防"猜当真相"）**：LLM 分类结果（temp 0.1）无论多自信，先过 `_confine_untrusted_profile_buckets`——**只有 recent_interactions/uncertain_notes 原样保留，其余 4 段全压进 uncertain_notes**；随后把**账本事实**（fact_claims，字段含 polarity/cardinality/stability/authority/status）按 profile_section 前置合入。规则：精确重复只增强原 claim；显式 supersedes 才失效；单值槽异值新 claim 进 conflicted 不静默覆盖。模型改写一律 `summary_derived+uncertain`。
- 版本化快照 + 人工 override 并存（指纹相同只续期不建新版本）；写路径 enqueue 后台 60s 刷新。

### 4. 反馈纠错
- 反馈以"任务"形式进（非即时判定）：query_memory 执行时打 `memory_feedback_task`（query 快照 JSON），`due_at = 查询时间+12h`——窗口内用户追加消息才构成反馈语境。
- 判定：信号词预筛（"不对/记错了/不是/应该是…"，滤 "哈哈/好的" 噪声）→ LLM 分类 `confirm|reject|correct|supplement|none` + confidence + target_hashes 强校验。
- 执行：**仅 reject/correct 且 confidence ≥ 0.85 自动执行**。reject→FORGET（strength=0、is_inactive=1，行保留可回退）；correct→先 forget 旧关系再以 chat_summary 源写回纠正三元组（supersedes_hash），失败按快照恢复；随后给源头段落打 `paragraph_stale_relation_marks`。
- **失效三路联动硬过滤**：检索藏掉关联关系已 inactive 的段落、画像剔除被 mark 段落、后台重建 Episode。管理侧整单 rollback。
- 主动改记忆走 preview→confirm（`memory_fuzzy_modify_plans` 状态机，默认禁止模型自作主张批量改库）。

### 5. 记忆演化/维护
- **半衰期只作用于"关系记忆"且惰性**：`retention_at = strength × 2^(-elapsed/24h)`，DB 只存 `retention_strength + retention_anchor_at + next_lifecycle_at`，分数用时现算（零写放大）；段落不走年龄衰减（显式 expires_at 才过期）。
- 1h tick 维护：到期行预排 `threshold_crossing_at` 用索引取；衰减 ≤0.1 且冻结超 24h → 自动软删；ACCESS +0.05(1−c)（冷却 3600s，≥0.15 复活）；REINFORCE +0.5(1−c) 锚点移 now；WEAKEN ×0.5；FREEZE/FORGET 墓碑。
- **protect 是独立字段非事件**：`protected_until` + pinned（remember_forever）；被保护行退出到期评估+禁止自动纠正。inactive=硬过滤而非降权；protect/pinned 不提分只"别动它"。
- **soft delete 两段式**：同一 IMMEDIATE 事务内 ①行内 is_deleted + 关系整行搬 `deleted_relations` 墓碑 ②建 `delete_operations`（**全量 JSON 快照**）；向量/图清理只入 Outbox 异步消费；purge 留 24h grace。完整链"decay 冻结→24h→软删→24h→purge"双安全窗口。管理操作全记 `memory_v5_operations` 审计行。

### 6. 异步沉淀（背景任务调度原语）
- 纯 asyncio 任务注册表：`_ensure_background_task` → `asyncio.create_task`，统一 loop=sleep(interval)→查开关→干一批→异常记日志下轮重试（崩溃安全）。13 类任务。
- Episode 生命周期：任何段落写/纠错/删除 → 写事务内 `desired_revision++`；消费 `process_episode_source_rebuild_batch`：claim（租约）→ LLM plan（只在后台 loop 内同步 await）→ publish revision CAS → 失败指数退避；新 revision 到达 supersede 旧任务。切分按时间连通（间隙>24h 断开），块限 20 段/6000 字，LLM 输出硬校验无遗漏无重复；`input_fingerprint` 未变直接复用旧 episode 不重调 LLM；**LLM 失败用确定性兜底摘要（llm_confidence=0）——模型挂了照常产出**。
- 防并发四层：写路径 fire-and-forget → 队列租约 CAS → 操作级 asyncio 锁 → 跨进程文件锁（一数据目录仅一写者）。

### 7. 与宿主集成（对话侧）
- 统一入口 `SDKMemoryKernel` facade，宿主经 `AMemorixHostService.invoke` 网关分发；内核启动前写操作入 JSONL 启动队列回放。
- 宿主侧只调用 ~30 语义化方法（search_memory / ingest_summary / ingest_text / get_person_profile / maintain_memory…），分三类：
  ① **LLM 工具（模型主动调）**：query_memory / query_person_profile；
  ② **自动注入（无工具调用）**：启发式记忆注入 + 画像注入；
  ③ **消息后写回钩子**：`MemoryAutomationService.on_message_sent`（聊天发消息后触发 ChatSummaryWriteback 消息数阈值摘要写回 + PersonFactWriteback 后台 LLM 抽人物事实）。

## 二、MaiBot 对话侧怎么用记忆/风格（对 Robot chat.py 的直接参考）

不是把记忆塞 System Prompt，而是 **planner 一次性注入分通道【内部参考】消息**（`reasoning_engine._build_planner_injected_user_messages`），全部带"仅供内部推理、不要逐字复述、冲突以当前对话为准"约束：

1. **启发式记忆**（`maisaka/memory/heuristic_injector.py`）：
   - 会话累计消息 ≥ 20 条才触发；且距上次 ≥ 180s、新增 ≥ 60 条（节流）；
   - 先让 LLM 把最近窗口生成一句**"聊天印象"**（当前话题），**用印象当检索 query**（比裸用户消息准）；
   - 结果缓存 300s、截 ≤900 字符注入。
   - Robot 对照：`_build_query` 每轮用"消息+最近4轮"裸文本直查，费且糙。
2. **画像注入**（`person_profile.py`）：对当前说话人/提及人最多 3 人查画像，拼【人物画像-内部参考】块。
3. **表达习惯**（`maisaka_expression_selector.py`）：从表达库选 0-N 条 → 子代理 LLM 二次精挑 → 格式成 `当"X"时可以用"Y"表达` 参考块注入。

## 三、MaiBot 说话风格学习（learners/）—— 三套闭环

| 学什么 | 模块 | 存储 |
|---|---|---|
| 口头禅/句式/语气 | `expression_*` | 「情景→说法」规律 + count 频次（同 situation+style merge，count+1，最近10条 LLM 重概括 situation）|
| 黑话/新词 | `jargon_*`（learner→miner→explainer）| 词条+含义+范围；阈值 4/8/25/100 触发三阶段含义推断，≥100 is_complete 封顶 |
| 场景化互动 | `behavior_*` | 场景画像标签簇（domain/need/attitude）+ 行为路径（action/outcome，actor/learning_type 分离自省/观察）|

- **采集时机**：上下文裁剪点（旧消息被裁丢弃瞬间）异步批量触发三个 learner 后台并行，≥10 条阈值+并发闸门——**学习零主链路开销**（对应 Robot 可在 consolidate/裁剪时顺带学风格）。
- **审核双环**：写库前 AI 自审（四准则：泛用性/不涉人名…留痕 review_logs）→ WebUI 人工 approve + `expression_checked_only` 只用已审条目。
- **使用**：参考文本注入 LLM 上下文让模型自然吸收（非模板替换）；**注入文案自带身份边界**（自省/观察分离、"结合身份酌情借鉴"）——正契合陪护"学老人风格但保持机器人身份"红线。
- **维护**：feedback 闭环写回 score，行为闲置天数衰减触底 enabled=False 自动下线（用进废退）。
- **边界**：无硬编码脏话表，靠 prompt 规则（不学 SELF/人名/具体名词）+ 代码过滤（昵称/表情占位/prompt 示例泄漏/单字词）+ 写库前 AI 审核 + 人工闸门。

## 四、Robot 现状 vs MaiBot 对照表

| 维度 | Robot（LLM/ 后端） | MaiBot | 差距 |
|---|---|---|---|
| 对话记忆使用 | 每轮 recall_v3 全量注入（档案+核心30+RAG Top3+图谱一跳）| 节流式：印象检索 + 画像/表达分通道一次性注入 | 召回糙、每轮都查（贵）|
| 摘要/事件沉淀 | consolidate 空闲30s/话题结束，**请求线程内** LLM 整理 | 消息数阈值 + 后台租约异步，external_id 幂等 | 线程内阻塞 + 无幂等防重 |
| 写入去重 | 服务端向量相似度兜底（0.55）| external_id 三层幂等 | 有升级路径 |
| 记忆可靠性 | 医疗/身份只读红线（比 MaiBot 严）；其余模型写了就生效 | 账本分层：AI 猜测压 uncertain，人工才定稿；冲突显性 | 缺"防 AI 猜错当真"分层 |
| 纠错 | /api/memories reject = 物理删；correct_instant 即时改核心记忆 | 12h 窗口反馈任务 + confidence≥0.85 自动 + stale-mark 三层撤退 + 全量可回滚 | 缺窗口化判定与软失效联动 |
| 遗忘/强化 | TTL 到期物理删 | 惰性半衰期 + 保护/强化 + 软删两段式 + 回收站 | 缺半衰期/保护/回收站 |
| 说话风格 | PERSONA 写死 + 画像一句 style | 表达/黑话/行为三闭环学习 + 注入参考 + 审核 | 完全缺失学习 |
| 检索融合 | 单路 Chroma 语义 + 图谱一跳 | 语义+稀疏BM25+图谱双池 + 校准 + RRF + 动态阈值 | 多路分数不可比未校准 |

## 五、对 Robot 最有借鉴价值清单（按性价比）

### 记忆侧 Top5（建议实施顺序）
1. **external_id 三层幂等**（~20 行，先做）——根治摘要/沉淀并发重复。
2. **账本定稿制 + AI 猜测压 uncertain 区**（安全红线级）——防把模型归纳当老人真相（养老场景错一条记忆可能误导健康决策）。
3. **否定=软失效 + stale-mark 三层联动**——老人说"记错了"后不复发、可回滚、全链路留痕。
4. **写事务内入队 + 后台租约消费**（队列表+asyncio task 即可，不需要中间件）——LLM 沉淀移出请求线程。
5. **惰性指数半衰期 + 保护/强化**——"会遗忘/可巩固/可保护"的护理偏好。

### 对话侧
- `_build_query` 升级为"聊天印象"式检索 + 分通道注入（更准更省）；注意 HISTORY_WINDOW 内滚动窗口 + 摘要已类似其短中长期分层。

### 风格侧 Top5（learners 结论）
1. 裁剪点批量后台学习（零流量、免语录库）
2. "当 situation 可用 style"规律 + 只注入参考块由 LLM 自然吸收
3. 写库前自审 + 审核日志 + "只用已审条目"开关
4. 反馈闭环 + 用进废退自动下线
5. 含义三阶段推断 + 阈值触发 + 封顶

### 可选升级（性价比次之）
- 多路分数校准（score_calibration.py 180 行可平移）+ 当次分布动态阈值——解决 Chroma+Kuzu+稀疏三路分数不可比。
- 软删两段式 + delete JSON 快照 + Outbox 清 Chroma（需自己做 Chroma 幂等 delete）。

## 六、落地路线建议（供后续排期）

**P0（安全/防重复，小改动）**：external_id 幂等 + reject 软删除/回收站 + 账本分层。
**P1（架构）**：沉淀后台化（脏标记队列）+ stale-mark 纠错联动。
**P2（体验）**：对话印象式检索注入 + 表达习惯注入 + 风格学习（expression 先行）。
**P3（锦上添花）**：半衰期演化/强化/保护、多路校准、导入中心、检索调优。

> 调研备注：MaiBot 记忆 v2.0 无内置"学风格但保身份"开关，但其参考注入文案与 actor 分离（自省/观察）设计正是陪护要的边界措辞。文档 `docs/maibot参考/memory-system.md`、`learning.md` 已与 MaiBot 官方 manual 一致。
