## 二、⚠️ 已知问题（2026-09-02 已修复）

1. **【已修复】`use_ekf:=true` 死开关**：原 odom.launch.py 只声明参数没拉起 EKF 节点。
   修复内容：
   - `odom.launch.py`：新增 `ekf_filter_node`（robot_localization/ekf_node，参数=ekf_params.yaml，
     remap odometry/filtered→/odom_filtered），仅当 `use_ekf:=true` 且 `odom_source:=chassis` 时启动；
   - `chassis_driver.py` + `chassis_params.yaml`：新增 `publish_tf` 参数（默认 true）；
     use_ekf 模式下 odom.launch.py 强制传 `publish_tf=false`（底盘只发 /odom 原始数据），
     odom→base_link TF 由 EKF 统一发布，避免双发布冲突；
   - `ekf_params.yaml`：odom1（rf2o /odom_laser）默认注释掉，避免无 rf2o 数据时的持续告警。
   用法：`ros2 launch robot_bringup bringup.launch.py mode:=mapping odom_source:=chassis use_ekf:=true`
   （底盘接入后用；无底盘 rf2o 兜底时不要开 use_ekf）。

2. **AMCL `robot_model_type: "differential"`**（nav2_params.yaml 第 33 行）：Humble 的 nav2_amcl 兼容 legacy 名，但新版推荐插件名
   `nav2_amcl::DifferentialMotionModel`（linorobot2 即用此）。上板核对后若 AMCL 起不来优先改这里。

3. **默认地图文件不存在**：`maps/` 目录只有 README.md，各 launch 默认 `maps/my_map.yaml` 是占位值 → 上板必须显式 `map:=<实际路径>`，或先建图。

## 三、上板版本核对命令（依赖装完后执行，逐条确认）

```bash
# 1. 依赖版本确认
apt list --installed 2>/dev/null | grep -E "ros-humble-(navigation2|nav2-bringup|slam-toolbox|robot-localization)"

# 2. bt_xml 路径存在性
ls /opt/ros/humble/share/nav2_bt_navigator/behavior_trees/ | grep -E "navigate_(to_pose|through_poses)_w_replanning_and_recovery"

# 3. nav2_bringup launch 文件名（Humble 应有 localization_launch.py + navigation_launch.py）
ls /opt/ros/humble/share/nav2_bringup/launch/

# 4. AMCL 参数核对（跑起后）
ros2 run nav2_amcl amcl --help 2>&1 | head   # 或起导航后: ros2 param get /amcl robot_model_type

# 5. slam_toolbox 参数名抽查（mode/restamp_tf/transform_publish_period 是否被接受）
ros2 run slam_toolbox async_slam_toolbox_node --show-params 2>/dev/null | grep -E "restamp_tf|transform_publish_period|base_frame"
```

## 四、上板执行顺序（与 README 一致，验证点逐步卡）

```bash
# 0. 装依赖（网络慢可续；已完成则跳过）
sudo apt install ros-humble-navigation2 ros-humble-nav2-bringup ros-humble-slam-toolbox ros-humble-robot-localization

# 1. 上传 + 编译（install/ 里旧 launch 必须重建）
#    本地: scp -r D:\_project\Robot\ros2_car → 板卡 /home/sunrise/Robot/ros2_car
#   ⚠️ 路径勘误：板卡实际路径是 /home/sunrise/Robot/ros2_car，不是 ~/ros2/car_ws
cd /home/sunrise/Robot/ros2_car && colcon build --symlink-install
source install/setup.bash

# 2. 逐级验证
ros2 launch robot_bringup lidar.launch.py && ros2 topic hz /scan        # 雷达出数 10Hz
ros2 launch robot_bringup odom.launch.py odom_source:=rf2o               # 无底盘先 rf2o 兜底
ros2 run tf2_ros tf2_echo map base_link                                  # TF 全链
# 有底盘时: odom_source:=chassis（记得先标定 chassis_params.yaml，见 README「标定」+ ROS2导航调试经验.md）

# 3. 建图
ros2 launch robot_bringup bringup.launch.py mode:=mapping odom_source:=chassis
ros2 run teleop_twist_keyboard teleop_twist_keyboard                     # 另开终端遥控逛一圈
# 存图（async slam 的 /map 按需发布，map_saver 可能报 Failed to spin → 重试几次）
ros2 run nav2_map_server map_saver_cli -f /home/sunrise/Robot/ros2_car/maps/my_map

# 4. 导航
# ⚠️ 已知 bug：bringup mode:=navigation 会丢 map 参数（map_server: yaml_filename not initialized）。
#   应改成分步：先起基础节点(lidar+odom+robot_state_publisher)，再直接跑 navigation.launch.py
ros2 launch robot_bringup navigation.launch.py map:=/home/sunrise/Robot/ros2_car/maps/my_map.yaml
# rviz 里 2D Pose Estimate 初始化 + "Nav2 Goal"(nav2_rviz_plugins/GoalTool) 发目标
#   （勿用旧 "2D Goal Pose"/SetGoal——发 /goal_pose，Nav2 不订阅）

# 5. 底盘接入后标定（chassis_params.yaml）：轴方向/轮径/旋转半径，再核对 AMCL/EKF
```

## 六、上板实测补充（2026-09-05 定稿）

本清单静态预估与实测的差异补充，详见 `ROS2导航调试经验.md`：

1. **AMCL robot_model_type**（本文二.2 预警项）实测**确需改**：`"differential"`→`"nav2_amcl::DifferentialMotionModel"`，否则 AMCL 配置即崩。
2. **controller_server 两处 `general_goal_checker` 缺 `plugin`**：`nav2_params.yaml` 里 controller 与 waypoint 都少了
   `plugin: "nav2_controller::SimpleGoalChecker"`，会 FATAL `Can not get 'plugin' param ... general_goal_checker`。
3. **rt导航别走 bringup**：双层 include 下 nav2 的 RewrittenYaml 对 `map`/params 处理丢参（map_server、controller 都起不来），
   用"基础节点 + navigation.launch.py 直连"。
4. **bt_navigator 残余阻塞**：nav2 无条件创建 navigate_through_poses 服务器并加载其 BT，激活时 1s 内等不到 `backup` 动作即失败
   （去插件无效）。当前定位+controller/planner/behavior 已 active，仅 bt_navigator 未通。
5. **底盘轴向**：odom `sign_vx=+1/vy=-1/wz=-1`，命令侧 `chassis_driver.py` 对 `vy/wz` 取反镜像（vx 不动），真机目测定稿。
