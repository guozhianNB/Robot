# 人脸识别操作手册（命令速查）

> 只想敲命令的话看这一份就够。原理与坑见 [人脸识别注意事项.md](人脸识别注意事项.md)。
> 所有命令都在**项目根目录**（`D:\project\Robot`）下执行；把 `.\.venv\Scripts\python.exe` 当作"python"即可。

## 0. 三条命令速查（最常用）

| 我要做什么 | 命令 |
|---|---|
| **添加新成员** | `python scripts\update_elder.py <uid> --name 姓名 --nickname 称呼`<br>再 `python scripts\face_check.py --live --enroll <uid> --frames 5` |
| **检测人脸是否在数据库里** | 图片：`python scripts\face_check.py --photo 照片.jpg`<br>摄像头：`python scripts\face_check.py --live`<br>只看库里有谁：`python scripts\face_check.py` |
| **删除成员** | 预览：`python scripts\update_elder.py <uid> --delete`<br>执行：`python scripts\update_elder.py <uid> --delete --yes` |

> 三个脚本都**不需要你手动启后端**（`face_check.py --live` 会自己起停摄像头服务与后端）。
> 建议在你自己的终端里跑：DSH/沙箱环境访问摄像头需要额外授权，你本地终端没有这层限制。

### 不想敲命令？用图形界面（同一套底层）

```powershell
.\.venv\Scripts\python.exe vision\vision_test_start.py
```

启动后是一个**一级小窗**，三个按钮分别对应上面三条流程：

| 按钮 | 对应命令 | 说明 |
|---|---|---|
| ① 人脸录入 | `update_elder.py <uid> --name … --nickname … --bed … --age …` + 采样 | 二级小窗实时画面，**镜头前有脸**才让点「开始录入」；然后弹三级小窗填姓名/称呼/床位/年龄（**uid 自动 = 前一个 uid + 1**）；录入完成显示「已录入」，3 秒后回一级小窗。**没检测到人脸就直接退出，档案和样本库都不动** |
| ② 人脸检测 | `face_check.py --live` | 二级小窗实时画面，把**老人的姓名画在对应人头上**（不在库里显示"未知" + 相似度）；底部有稳定/可切换判定 |
| ③ 删除数据 | `update_elder.py <uid> --delete --yes` | 输入姓名 → 反查 uid → 候选列表里选中 → 确认删除（先自动备份数据库）→ 删完回一级小窗 |

退出：**Ctrl+C**（或关掉窗口）。没有摄像头时加 `--source mock` 也能把界面点开看流程。
细节（含"人脸检测为什么不是去起 `face_check.py` 子进程"）见 [README.md](README.md) 的
「图形界面：人脸测试台」一节。

## 1. 添加新成员

**两步，顺序不能反**（挂脸时 uid 必须已在档案里，否则这个人在系统里是"未知角色"，
语音/记忆/提醒都会不对）。顺序错了会被脚本拦住并提示。

### 第 1 步：建档案

```powershell
python scripts\update_elder.py elder_003 --name 张桂芳 --nickname 张奶奶 --bed 3-12 --age 78
```

| 参数 | 说明 |
|---|---|
| `<uid>` | 成员的编号，自己定（如 `elder_003` 或拼音 `zhang_guifang`）。**别用 `admin`**（管理员专用值）；**建好别再改**（它是主键，声纹/人脸样本目录都用它命名） |
| `--name` | 姓名（必填才能建档） |
| `--nickname` | 称呼，AI 与界面优先用它（如"张奶奶"） |
| `--bed` / `--age` / `--gender` / `--notes` / `--style` | 床位 / 年龄 / 性别 / 备注 / 说话风格，都可省 |

- 先看看会建成什么样（**不写库**）：加 `--dry-run`
- 看现有成员：`python scripts\update_elder.py --list`
- 建完改成别的字段（例如补年龄）：再跑一次同样的命令带上新参数即可（**只改你点名的字段，其他不动**）

### 第 2 步：挂人脸（对着摄像头）

```powershell
python scripts\face_check.py --live --enroll elder_003 --frames 5
```

- 会先给 6 秒倒计时（提醒你坐好），然后拍 5 帧、再连续探测 6~8 次并给出结论
- 拍照前：**开灯、坐近、正对镜头**（光照/距离直接决定识别率）
- **不满意就再跑一遍这条命令** —— 它是**追加**样本（旧的不删），这正是提升识别率的正解
- 想用**现成照片**挂脸（不用摄像头，手机拍的也行）：
  ```powershell
  python -m LLM.face_api enroll-photo elder_003 D:\照片\1.jpg D:\照片\2.jpg
  ```
- 有一整个文件夹、按"每人一个子目录"整理的数据集（兼容旧项目布局 `<目录>/<人名>/*.jpg`）：
  ```powershell
  python -m LLM.face_api enroll-dir D:\旧数据集
  python -m LLM.face_api enroll-dir D:\某个人的照片 --uid elder_003   # 整个目录都算这个人
  ```

## 2. 检测人脸是否在数据库里

### 方式 A：用一张图片（最快，不需要摄像头、不需要后端）

```powershell
python scripts\face_check.py --photo 照片.jpg
python scripts\face_check.py --photo vision\testdata\group_solvay.jpg    # 多人合影
```

输出示例与读法：

```
  检出 1 张脸，返回 1 张：
    #1 检测分=0.664  认出=fuze（000）  相似度=0.7821  与第二名差距=0.31  (ok)
       └ 检测分：YOLO"框得多准"（门槛 0.45）
       └ 认出：库里最像的人；显示"未知"= 没到进库阈值（0.45）
       └ 相似度：越接近 1 越像（同一个人通常 0.5~0.97，看光照条件）
结论：认出 fuze（000）（相似度 0.7821）
```

### 方式 B：用摄像头（"能不能认出我"）

```powershell
python scripts\face_check.py --live                # 连续探测 8 次
python scripts\face_check.py --live --rounds 12    # 想测久一点
```

输出是一张逐帧表格，重点看两列：**"认出的是谁"** 和 **"相似度"**；末行给结论。

| 结论 | 含义 |
|---|---|
| `switchable=True` | 认出且稳定 → 系统可以据此切换主体 ✅ |
| 能认出但 `switchable=False` | 看 `reason`（下表） |
| `认出=未知` | 相似度低于 0.45：库里没这个人，或光照/角度差太远 |

**`reason` 怎么处理**（表格里也会打印）：

| reason | 怎么办 |
|---|---|
| `identity_low_score`（最常见） | **去补拍当前光照/距离的样本**：`--live --enroll <uid> --frames 3` |
| `not_enough_frames` | 保持不动多对一会儿镜头（约 3~4 秒） |
| `low_score` | 开灯 / 坐近 / 别侧脸 |
| `identity_unstable` | 别晃、别扭头 |
| `multiple_faces` | 画面里只留一个人（系统不猜） |
| `no_identity` | 库里没这个人，或换过摄像头（细节看下一条 Q） |
| `frames_reset` | 正常过渡，再连测几帧 |
| `no_face` | 人不在画面里 |

### 方式 C：只看"库里都有谁"

```powershell
python scripts\face_check.py            # 状态：模型是否可用 + 门槛 + 已记住谁、各几张
python -m LLM.face_api people           # 库概况（JSON：人数/张数/每人几张/谁的样本偏少）
```

> 相似度低于阈值**不代表照片有问题**，而是"这张脸和库里存的样子不够像"。
> 想让它认得，用这张照片注册一次再测：
> `python -m LLM.face_api enroll-photo <uid> 这张图.jpg`

## 3. 删除成员

**先预览**（列出每张表要删多少行 + 要删的样本文件，**什么都不删**）：

```powershell
python scripts\update_elder.py elder_003 --delete
```

**确认执行**（会自动备份数据库 → 连根删 → 如果他是当前"说话的人"则清空会话主体）：

```powershell
python scripts\update_elder.py elder_003 --delete --yes
```

- **删的是全部**：档案、记忆（含核心记忆/RAG/画像/表达）、对话历史、提醒、工具日志、回收站记录、
  声纹样本、人脸样本 —— 只删档案会留下孤儿数据，所以做成"连根删"
- **不可撤销**，但会自动备份到 `LLM/data/backup/brain-<时间>.db`（该目录不入库）
- **恢复**：停掉后端 → 把备份文件覆盖回 `LLM/data/brain.db`
- 建议**在后端停止时执行**（避免它同时读写同一个库）
- 只想删脸、保留档案：`python -m LLM.face_api delete <uid>`

## 4. 命令参数速查

### `scripts\update_elder.py`（档案）

| 用法 | 作用 |
|---|---|
| `update_elder.py --list` | 列出所有成员（uid / 姓名 / 称呼 / 床位 / 年龄 / 角色） |
| `update_elder.py <uid> --name X ...` | 档案不存在则**新建**；已存在则**只改点名的字段** |
| `update_elder.py <uid> ... --dry-run` | 只打印会改成什么/会新建什么，不写库 |
| `update_elder.py <uid> --delete` | 预览删除（连根删） |
| `update_elder.py <uid> --delete --yes` | 执行删除（先自动备份） |

可改字段：`--name --nickname --bed --age --gender --notes --style`

### `scripts\face_check.py`（人脸自测）

| 用法 | 作用 |
|---|---|
| `face_check.py` | 只看状态（模型、门槛、库里谁、各几张）——不碰摄像头 |
| `face_check.py --photo 图` | 用图片识别（不需要摄像头/后端） |
| `face_check.py --live` | 摄像头连续探测（自动起停摄像头服务与后端） |
| `face_check.py --live --rounds N` | 指定探测次数（默认 8） |
| `face_check.py --live --enroll UID --frames N` | 先注册/补拍 N 帧，再探测 |
| `face_check.py --live --enroll UID --force` | uid 没档案时也照样挂脸（**不推荐**） |

### `python -m LLM.face_api`（样本库，离线可用）

| 用法 | 作用 |
|---|---|
| `-m LLM.face_api status` | 模块 + 样本库状态 |
| `-m LLM.face_api people` | 列出已注册的人与样本数 |
| `-m LLM.face_api enroll-photo <uid> 图...` | 用照片注册（可多张） |
| `-m LLM.face_api enroll-dir <目录> [--uid U]` | 批量导入 `<目录>/<人名>/*.jpg` |
| `-m LLM.face_api identify 图...` | 识别图片里的人是谁（不推进"连续 N 帧"判定） |
| `-m LLM.face_api delete <uid>` | 删除某人的**人脸样本**（档案保留） |

## 5. 常见问题

**Q：需要先启动后端吗？**
A：上面这些命令都不需要。`face_check.py --live` 会自己起停摄像头服务与后端。
只有你要用**浏览器界面**（`http://127.0.0.1:8000/admin`）或让别人调 HTTP 接口时才需要启后端：
`python -m uvicorn LLM.server:app --host 0.0.0.0 --port 8000`

**Q：终端里 `reason=no_identity` 是什么意思？**
A：**"检测到了人脸，但说不清这是谁"** —— 人脸这一关过了（`stable` 可能是 `True`），
识别（ArcFace 比对样本库）那一关没给出人名。它是**结论**，具体卡在哪一步要看**每个人脸自己的**
`identity_reason`（`face_check.py --live` 现在会把它连同相似度一起打出来）：

| `identity_reason` | 含义 | 怎么办 |
|---|---|---|
| `below_threshold` | 相似度没到进库阈值（默认 0.45）—— 库里没这个人，**或**当前光照/距离/角度与你注册时差太远 | 先确认库里有你（`--list`/`people`），再在当前条件下补拍：`--live --enroll <uid> --frames 3` |
| `empty_library` | 样本库是空的，一个人都没注册 | 先注册：`--live --enroll <uid> --frames 5` |
| `ambiguous` | 库里有两个人的分数咬得很近（差距 < 0.03），系统宁可不认 | 各补拍几张拉开差距，或确认没把同一人注册成两个 uid |
| `embed_error:…` | 提指纹报错（对齐/模型问题） | 把原始报错发我 |

> 常见误区：`no_identity` **不是**"模型坏了"也不是"照片不像我"。
> 实测同一个人在不同条件下相似度可从 0.9 掉到 0.36，掉到阈值以下就报 `no_identity`。
> 另注：进了库也不一定立刻 `switchable` —— 还要连续几帧身份一致（`identity_low_score`/`not_enough_frames` 是那个阶段的事）。

**Q：为什么照片明明是我，却显示"未知"？**
A：库里的样本是"某一次拍摄条件下的样子"。换光照/距离/角度后相似度可能从 0.9 掉到 0.45。
先确认库里确实有这个人（`--list` / `people`），然后**在当前条件下补拍几张**再测。

**Q：补拍会把旧样本删掉吗？**
A：不会，是**追加**（每人上限 20 张，可用 `conf.FACE_LIB_MAX_SAMPLES_PER_UID` 调）。

**Q：uid 能用中文或 `admin` 吗？**
A：中文可以（但建议拼音，命令行更省事）；**`admin` 绝对不要**（那是管理员专用值，会被特殊处理）。

**Q：我把所有成员都删了，会不会又冒出"张建国"？**
A：会。后端启动时若档案表为空，会自动种一个演示档案（张建国 / elder_001）。想避免，就至少保留一个成员。

**Q：想调识别严格程度？**
A：改 `LLM/conf.py` 里的门槛，或临时用环境变量试（当前终端有效）：
`$env:FACE_MATCH_THRESHOLD="0.5"`（进库阈值）、`$env:FACE_IDENTITY_CONF="0.6"`（切换阈值）、
`$env:FACE_STABLE_FRAMES="3"`（连续帧数）。改完重跑命令即可。

**Q：检测/识别模型在哪、怎么重装？**
A：在 `vision/models/`（不入库）。重装：
`python -m vision.face --download`（检测，12 MB）、`python -m vision.faceid --download`（识别，14 MB）。
